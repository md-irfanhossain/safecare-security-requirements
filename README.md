# SafeCare Hospital Security Requirements Case Study

## Overview

SafeCare was a university group software engineering project based on the design of a proposed digital hospital management and monitoring system.

This repository is an individual portfolio summary of my own contribution to the project. It does not contain the original assessed coursework, group submission, or other team members' work.

My role focused on systems analysis and requirements engineering, with particular attention to security, privacy, legal and operational requirements.

## My Role

My contribution focused on:

- Systems analysis
- Functional and non-functional requirements
- Security requirements
- Privacy and data-protection considerations
- Legal and regulatory considerations
- Access-control requirements
- Reliability and resilience requirements

The aim was to define requirements clearly enough for the later design and development stages of the system.

## Security and Privacy Requirements

The proposed SafeCare platform handled sensitive patient and visitor information, so security and privacy were important parts of the requirements.

Key requirements considered included:

### Access Control

The system proposed multiple methods of controlling access, including:

- RFID badges
- QR codes
- Biometric authentication concepts
- Authorised access to restricted areas
- Detection of unauthorised access attempts

### Data Protection and Privacy

The requirements considered:

- GDPR
- Data protection
- Confidential handling of patient and visitor information
- Consent management
- Encryption of sensitive information
- Secure transmission of data using TLS

### Monitoring and Security Alerts

The proposed system included:

- Central security monitoring
- Real-time security alerts
- Detection of unregistered access attempts
- Location monitoring for authorised operational purposes
- Security cameras and monitoring systems

### Availability and Resilience

Because a hospital system may support critical operations, the requirements also considered:

- System reliability
- Backup capability
- Continued operation during network or power outages
- Emergency response capability
- Offline capability
- Maintainable system architecture

## Functional Requirements Considered

Examples of requirements included:

- Patient and visitor pre-registration
- Digital QR identification
- Access-control verification
- Real-time alerts
- Emergency procedures
- Patient and visitor location information
- Database-backed record management

## Development Approach

The project compared different software development approaches and selected Structured Systems Analysis and Design (SSAD).

SSAD provided a structured process covering areas such as:

- Requirements
- Data-flow analysis
- Design
- Implementation
- Maintenance

For a system handling sensitive healthcare information, structured documentation and traceability were considered useful for supporting legal and data-protection requirements.

## Cybersecurity Relevance

This project helped me develop experience in thinking about security before implementation rather than treating cybersecurity as an afterthought.

The project strengthened my understanding of:

- Security requirements engineering
- Privacy by design
- Identity and access management concepts
- Authentication and authorisation
- GDPR and data protection
- Encryption requirements
- System resilience
- Security monitoring requirements
- Risk-aware system design
- Translating business and legal requirements into technical requirements

## What I Learned

The project showed me that cybersecurity is not only about detecting attacks after they occur.

Security decisions should also be considered during requirements gathering and system design.

For systems that process sensitive information, requirements need to consider who can access data, how information is protected, how incidents are detected, how services remain available, and how legal obligations affect technical design.
